什麼是網路爬蟲?

網路爬蟲(Web Scraper / Crawler)是一支自動拜訪網頁、讀取內容、並把你要的資料「摘」下來整理好的程式。

打個比方:你想知道 10 個購物網站的某款耳機價格。手動做法是——開 10 個分頁、逐頁找到價格、複製、貼進 Excel、再下一個……爬蟲的做法是——你告訴它「去這 10 個網址,找到價格數字,存成表格」,然後去泡杯咖啡,回來資料就好了。網站從 10 個變 1000 個,它也不會喊累。

你每天都在享受爬蟲的成果

服務背後的爬蟲在做什麼
Google 搜尋爬蟲(Googlebot)日夜爬遍全網,建立搜尋索引
比價網站定期爬各大電商,更新商品價格
新聞聚合 App爬各家新聞網站,匯集標題與摘要
AI 語言模型用大量爬來的網頁文字當訓練材料
房價分析、輿情分析爬公開資料做統計與研究
⚠️ 先講最重要的一件事:爬蟲是中性的工具,但「爬什麼、爬多快、拿去做什麼」有分寸。公開資料、低頻率、註明來源,通常是安全的;個資、需付費登入的內容、大量轉售,是紅線。第 8 章我們會把禮儀與法律界線一次講清楚。

Chapter 1⏱ 約 10 分鐘

🚇 HTTP:爬蟲的地下鐵

🎯 這章你會學到:看懂「請求 → 回應」的對話,讀懂狀態碼,並親手發出你的第一個模擬 HTTP 請求。

瀏覽器是怎麼看到網頁的?

當你在網址列輸入網址按下 Enter,背後發生的事是:

  1. 瀏覽器向伺服器發出一個 HTTP 請求(Request):「請給我這個網址的內容」
  2. 伺服器回一個 HTTP 回應(Response):狀態碼 + HTML 文件
  3. 瀏覽器把 HTML「畫」成你看到的漂亮網頁

爬蟲做的事一模一樣,只是省略第 3 步——不要漂亮的畫面,只要原始的 HTML 資料。理解了這一點,你就已經懂爬蟲的一半了。

🎮 互動:HTTP 請求模擬器
選一個情境,按「發送請求」,看看程式和伺服器之間到底傳了什麼。彩蛋:試著在 10 秒內連按 6 次「發送請求」!
😉 看到了嗎?你請求得太快,伺服器直接回了 429 Too Many Requests 把你擋下來。這就是真實網站對付粗魯爬蟲的方式——第 8 章會教你怎麼當個有禮貌的爬蟲。

讀懂狀態碼:伺服器的心情符號

狀態碼是回應的第一行,三個數字濃縮了伺服器想說的話:

狀態碼名字意思爬蟲該怎麼辦
200OK成功,資料在這放心解析 🎉
301 / 302Redirect搬到新網址了requests 會自動跟著走
403Forbidden拒絕你存取(常見於爬蟲被認出)檢查 User-Agent、放慢速度
404Not Found網址不存在檢查 URL,跳過或記錄
429Too Many Requests你太快了,被限流休息(看 Retry-After),降低頻率
500Server Error伺服器自己出錯稍後重試
📌 記憶法:2xx 成功、3xx 轉址、4xx 是「你」的問題、5xx 是「伺服器」的問題。
🎮 互動:狀態碼連連看
點一個狀態碼,再點它的意思。六組全部配對成功就過關!

GET 與 POST

GETPOST
用途取得資料(爬蟲 95% 用這個)送出資料(登入、表單、搜尋)
參數位置網址後面 ?page=2&q=python藏在請求內容裡
爬蟲場景抓列表、抓內容頁登入後才看得到的頁面
💡 User-Agent 是什麼?請求裡的一行自我介紹,告訴伺服器「我是誰」。瀏覽器的 UA 像一本護照;而 requests 預設的 UA 會老實說「我是 python-requests」——有些網站一看就把你列入黑名單(還記得剛才的 403 情境嗎?)。第 4 章開始我們都會帶著 UA 出門。
📌 本章重點爬蟲 = 請求 + 回應,跳過渲染2xx 成功、4xx 你的錯、5xx 伺服器的錯分頁規律藏在 ?page=User-Agent 是你的名片

Chapter 2⏱ 約 10 分鐘

🦴 HTML:網頁的骨架

🎯 這章你會學到:看懂標籤、屬性、巢狀結構,知道資料「藏」在網頁的什麼地方。

爬蟲拿到的 HTML 長得像這樣——一堆角括號。別慌,它其實只是一棵家譜樹:

<div class="book">            ← 開標籤(tag),class 是「屬性」
  <h3 class="title">銀河帝國</h3>   ← 文字內容:銀河帝國
  <p class="price">$320</p>
</div>                        ← 對應的關標籤
常見標籤用途爬蟲視角
<div> <span>萬用容器,分組用最常見的「資料盒子」
<h1>~<h6>標題文章標題常在這
<p>段落內文、描述
<a href="...">連結爬到新頁面的入口!
<table><tr><td>表格表格型資料的寶庫
<img src="...">圖片要抓圖就找 src 屬性
📌 class vs id:class 像「班級」,一頁可以有很多個 .book、.price;id 像「身分證字號」,整頁唯一。爬蟲 90% 的定位都靠 class。

家譜術語:爬蟲的方位語言

HTML 是一棵樹,所以文件和教學描述位置時都用「家人的稱呼」。先記住這四個詞,第 3 章的選擇器會立刻變得直覺:

術語意思在書店範例中
父元素(parent)直接上一層div.book 是 h3 的爸爸
子元素(child)直接下一層h3、p 是 div.book 的孩子
後代(descendant)下面任何一層(兒子、孫子…)h3 是 body 的後代
兄弟(sibling)同一層、同一個爸爸h3 和 p 互為兄弟
💡 這些方位直接對應下一章的選擇器語法:空格 = 找後代(任何深度),> = 只找直接子層。聽懂家譜,選擇器就通了。
🎮 互動:HTML 家譜樹探索器
點左邊原始碼裡的任何標籤,或點右邊樹狀圖的節點——兩邊會互相照亮,下方告訴你它在爬蟲眼裡是什麼。
網頁原始碼(點我!)

  <head>
    <title>書蟲書店</title>
  </head>
  <body>
    <div class="book">
      <h3 class="title">銀河帝國</h3>
      <p class="price">$320</p>

DOM 樹(點我!)
🌐 html
 ├─ 📄 head
 │   └─ 📝 <title> → 「書蟲書店」

🎯 CSS 選擇器:爬蟲的精準定位器

🎯 這章你會學到:學會用 CSS 選擇器在一堆 HTML 裡精準點名你要的資料——這是爬蟲最核心的技能,本章全程動手玩。

一個真實網頁的 HTML 可能有幾千行。爬蟲的關鍵問題是:怎麼從裡面精準撈出你要的那幾個元素?答案就是 CSS 選擇器——一套「點名語法」,BeautifulSoup 的 select() 完全支援它。

🐍 第一支爬蟲誕生

🎯 這章你會學到:用 requests + BeautifulSoup 寫出你人生第一支爬蟲,看懂每一行在做什麼。

兩位主角

  • requests —— 負責上網的「司機」:開著車(HTTP 請求)去伺服器載貨(HTML)回來。
  • BeautifulSoup —— 負責拆貨的「倉管」:把一團 HTML 文字變成好查詢的結構,讓你用 CSS 選擇器精準取貨。

完整的第一支爬蟲

scraper.py
import requests
from bs4 import BeautifulSoup

url = "https://example.com/books"
headers = {"User-Agent": "MyFirstScraper/1.0 (student@example.com)"}

# 1. 發送請求,拿到回應
response = requests.get(url, headers=headers, timeout=10)
response.raise_for_status()   # 狀態碼不是 2xx 就直接報錯

# 2. 交給 BeautifulSoup 解析
soup = BeautifulSoup(response.text, "html.parser")

# 3. 定位並萃取資料(第 3 章學的選擇器上場!)
site_name = soup.select_one("#logo").get_text(strip=True)
books = soup.select("div.book")
print("網站名稱:", site_name)
print("本頁共找到", len(books), "本書:")
for book in books:
    name = book.select_one(".title").get_text(strip=True)
    price = book.select_one(".price").get_text(strip=True)
    print("-", name, price)

逐行解剖

  1. requests.get(url, headers=..., timeout=10) —— 發 GET 請求。timeout 一定要設,否則伺服器不回應時程式會掛在那裡等到天荒地老。
  2. raise_for_status() —— 保險絲:如果回來的是 404/403,立刻報錯,不要傻傻解析一坨錯誤頁面。
  3. BeautifulSoup(response.text, "html.parser") —— 把 HTML 文字餵給解析器,變成可查詢的 soup。
  4. soup.select_one("#logo") —— 選擇器找到的第一個元素;get_text(strip=True) 取出乾淨的文字(去掉前後空白)。
  5. soup.select("div.book") —— 回傳所有符合元素的清單,配 for 迴圈一個一個處理。
  6. 在每本書的盒子裡再往下 select 書名和價格 —— 先框大範圍、再取小內容,這是爬蟲最重要的思考模式。

新手三大坑(先知道,少走彎路)

⚠️ 坑 1:沒帶 User-Agent 就 403。很多網站直接擋掉預設的 python-requests。永遠帶上 headers。

⚠️ 坑 2:對 None 呼叫方法。select_one() 找不到時回傳 None,接著 .get_text() 就會噴 AttributeError。養成習慣:el = soup.select_one(".price") 之後先 if el:。

⚠️ 坑 3:中文亂碼。如果 response.text 亂碼,手動指定 response.encoding = "utf-8" 再取 .text。

延伸:抓「連結」——爬蟲的傳送門

爬蟲不只能抓文字。屬性也常是目標——拿到 <a> 的 href,就等於拿到下一批要拜訪的網址,這正是爬蟲能「爬遍全站」的原因:

links.py
import requests
from bs4 import BeautifulSoup

resp = requests.get("https://example.com/books", timeout=10)
soup = BeautifulSoup(resp.text, "html.parser")

for a in soup.select("nav.menu a"):
    print(a.get_text(strip=True), "→", a["href"])

🎮 互動:你會推算分頁網址了嗎?

pagination.py
import time
import requests
from bs4 import BeautifulSoup

HEADERS = {"User-Agent": "MyFirstScraper/1.0 (student@example.com)"}
all_books = []                     # 一個大清單,累積每一頁的收穫

for page in range(1, 4):           # 想爬幾頁就填多少
    url = f"https://example.com/books?page={page}"
    resp = requests.get(url, headers=HEADERS, timeout=10)
    resp.raise_for_status()
    soup = BeautifulSoup(resp.text, "html.parser")

    for book in soup.select("div.book"):
        all_books.append({         # 每本書存成一個 dict
            "書名": book.select_one(".title").get_text(strip=True),
            "價格": book.select_one(".price").get_text(strip=True),
            "來自頁": page,
        })
    print(f"第 {page} 頁完成,目前累積 {len(all_books)} 筆")
    time.sleep(2)                  # 禮貌等待,別打爆伺服器

print("總共抓到", len(all_books), "筆資料")

robots.txt:網站掛在門口的告示牌

幾乎每個網站都會在根目錄放一份 robots.txt(試試 網址/robots.txt),告訴爬蟲「哪裡歡迎、哪裡請勿進入」。它是業界禮儀,不是法律條文——但違反它,往往同時違反網站服務條款,可能惹上法律麻煩。

限流與重試:工業級的基本功

polite.py
import time
import requests

HEADERS = {"User-Agent": "PoliteScraper/1.0 (+mailto:me@example.com)"}

def fetch(url, retries=3):
    for attempt in range(1, retries + 1):
        try:
            resp = requests.get(url, headers=HEADERS, timeout=10)
            if resp.status_code == 429:          # 被限流:照規定休息
                retry_after = resp.headers.get("Retry-After", "")
                wait = int(retry_after) if retry_after.isdigit() else 30   # 也可能是日期格式
                print(f"被限流,休息 {wait} 秒…")
                time.sleep(wait)
                continue
            resp.raise_for_status()
            return resp
        except requests.RequestException as err:
            print(f"嘗試 {attempt}/{retries} 失敗:{err}")
            time.sleep(5)
    raise RuntimeError(f"{url} 重試 {retries} 次仍然失敗")
嘗試 1/3 失敗:⏱ 連線逾時
嘗試 2/3 失敗:💥 連線被重設
嘗試 3/3 …✅ 成功!(狀態碼 200)

爬蟲黃金守則

⚖️ 能爬(綠燈):公開可見的資料 · 遵守 robots.txt · 低頻率(每請求隔 2~5 秒)· 註明資料來源 · 學術研究、個人專案

🚫 別爬(紅燈):需要登入/付費才能看的內容 · 個人資料(姓名+電話+住址…)· 爬來轉售或冒充原站 · 繞過驗證碼、帳號密碼等防護 · 高頻率打到影響網站服務

📌 一句話原則:「如果這件事很多人同時做,網站會不會壞掉?別人知道我在做,會不會不好意思?」任一答案是 yes,就先停下來想想,或直接寫信問網站管理員。

登入後才能爬?Session 與 Cookie

用 requests.Session() 可以像瀏覽器一樣「記住」登入狀態:先 POST 登入,之後的請求會自動帶上 Cookie。但要記得紅線——會員專屬內容通常禁止爬取與轉傳,登入前先看服務條款。

session = requests.Session()
session.post("https://example.com/login",
             data={"user": "me", "password": "***"})
resp = session.get("https://example.com/member")   # 自動帶上 Cookie
爬得很慢?並行與排程自動化

多頁面可以用 concurrent.futures 或 asyncio + httpx 並行加速,但並行 = 更高的請求頻率,務必更禮貌:同時最多 2~3 個請求、每次仍加延遲。想讓爬蟲每天自動執行,可用 Windows 工作排程器、macOS launchd 或 Linux crontab。

想更專業?認識 Scrapy 框架

Scrapy 是 Python 最知名的爬蟲框架:內建請求排程、自動重試、資料管道(清洗與存檔)、可擴充到分散式。學完本課的 requests + BeautifulSoup 再學 Scrapy 會非常順——因為概念完全相同,只是工具更強。
